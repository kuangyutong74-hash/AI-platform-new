# AI伯乐 · 探索星球（整合平台 1.0）

儿童天赋发现平台的统一入口。聊天观察、故事共创、深海基地重建和职业模拟器四个模块均已迁入本项目，四者地位平等。平台现分为学生端与老师/家长端，两端共用统一账号、作品、点评和行为证据数据。

## 项目结构

```text
整合平台1.0/
├─ app/                         星球首页与平台界面
├─ public/                      平台贴图和公共资源
│  └─ assets/collections/       作品与成长足迹的水彩插画
├─ modules/
│  ├─ chat/                     倾听之洲 · 聊天观察
│  ├─ story/                    想象之洲 · 故事共创
│  │  ├─ backend/
│  │  └─ frontend/
│  ├─ deep-sea/                 创造之洲 · 深海基地重建
│  └─ career/                   未来之洲 · 职业模拟器
├─ scripts/                     统一服务配置与工具
├─ 安装全部依赖.ps1
├─ 一键启动.ps1
├─ 检查服务状态.ps1
└─ 停止全部服务.ps1
```

## 账号与双端视角

- 注册前先选择“我是学生”或“我是老师/家长”；登录入口同样按角色分开，避免进入错误视角。测试阶段的成人端不再细分家长与老师身份。
- 账号可以自行填写，也可以留空自动生成。自动编号使用 `S+年份+4位序号`（学生）或 `A+年份+4位序号`（成人），账号全局不可重复且登录时不区分大小写。
- 注册只需设置登录密码；忘记密码时输入用户名和新密码即可直接重置，测试阶段不再使用额外找回码。
- 老师/家长注册后仅凭学生账号即可绑定，不需要学生密码；每个成人账号最多绑定 5 位学生，并可通过顶部常驻的“管理学生”继续添加或解除绑定。首次绑定后界面会立即切换，无需刷新。
- 成人只能读取已绑定学生的报告、作品和足迹，不能代替学生生成作品或提交探索证据。

## 学生端与老师/家长端

- 学生端默认进入“探索星球”，只保留“探索星球”“我的作品”“天赋藏宝图”。
- “我的作品”收录四个模块的完成成果；学生也可自行选择所属大陆，添加作品名称和内容。自主添加的作品单独保存，不参与天赋证据判断。
- “天赋藏宝图”使用天赋报告现有的儿童地图视角；学生端不能切换到成人报告。
- 老师/家长端默认进入当前学生的“天赋报告”，并保留“作品展柜”和“成长足迹”。
- “作品展柜”只读展示学生全部作品；老师/家长可以发表评论，点评会同步显示在学生的“我的作品”中。
- “成长足迹”从成人观察视角展示学生注册起点、各模块首次/最近完成时间、累计次数与可用时长。

## 作品与成长数据

- 点击主星球附近的“我的作品”或“成长足迹”星石即可进入；顶部导航和浏览器前进、后退同样可用。
- 两个页面共用统一账号，并从 `http://localhost:8020/api/explorer/collection` 读取真实证据记录。
- 当前账号还没有探索记录，或后端暂时不可用时，页面会显示明确标注的示例内容，不会把示例当成孩子的真实档案。
- “我的作品”同时提供全部作品与四枚模块高光，保留详情阅读、中文朗读、字号切换和成人点评。
- “成长足迹”从账号注册日开始，按模块展示首次使用、最近使用、累计次数与可用的累计时长；仍包含星路手账、未点亮提示和作品互跳。
- 桌面、平板和手机布局均保留大点击区域、键盘焦点、减少动态偏好和清楚的加载/错误状态。

四个模块的运行路径全部指向 `modules/`，不再依赖项目外部的旧目录。旧目录暂时保留，仅作为安全备份。

## Windows 环境要求

- Node.js `>=22.13.0`
- Python `>=3.8`

## 首次安装

在 PowerShell 中运行：

```powershell
.\安装全部依赖.ps1
```

脚本会为平台、聊天观察、故事共创前端、深海基地前端安装 Node.js 依赖，并为三个 Python 后端安装依赖。

## 一键启动全部模块

```powershell
.\一键启动.ps1
```

脚本会启动平台、统一账号、天赋报告和四个探索模块所需的九项服务。首页会先执行正式构建，再通过稳定的生产预览服务启动，避免 Windows 文件监听导致开发服务器卡死。脚本不再仅凭“端口已占用”判断服务正常，而会逐项检查访问地址，等待服务真正就绪后再打开 <http://localhost:4173>。日志统一写入 `.runtime/logs/`，首页构建详情位于 `整合平台.build.log`。

如果上次异常退出，或拉取代码后怀疑残留进程仍在运行，可使用：

```powershell
.\一键启动.ps1 -Restart
```

`-Restart` 只会回收统一服务配置中声明的十个本地端口（4173、5175、3000、8010、5174、8005、3001、8000、8020、8030），随后重新启动；不会扫描或结束其他端口上的 Node/Python 进程。

其他可选参数：

- `-NoOpen`：服务启动完成后不自动打开浏览器。
- `-TimeoutSeconds 90`：调整等待服务就绪的时间，默认 60 秒。

如果某个端口已被其他程序占用但对应服务无法访问，脚本会明确报告端口冲突，不会再把它误判成启动成功。

```powershell
.\检查服务状态.ps1
.\停止全部服务.ps1
```

停止脚本只停止本启动脚本记录的进程，不会结束电脑上的其他 Node 或 Python 进程。

## 只启动或检查整合平台


```powershell
npm run dev
npm run build
npm test
```

`npm test` 会依次执行正式构建、页面与数据契约测试、一键启动记录兼容测试，以及统一账号服务的后端测试。首次运行前请先执行 `安装全部依赖.ps1`。

只需检查前端构建时，可以运行 `.\构建检查.ps1`。
