# 伯乐小星 · 首页桌宠向导方案（细化版）

> 目标：把「四个散装模块」用一只住在星球上的引导精灵串成「一个会记住孩子兴趣的世界」。
> 本文在你上一版《模块串联方案》基础上，聚焦你提出的 **「首页桌宠向导 + 智能体驱动」** 这一条主线，做可行性确认与落地细化。

---

## 0. 主题确认 & 一句话结论

- 主题**就是「星球探索」**：首页 `app/components/PlanetHome.tsx` 是一颗可旋转的梦幻星球，四座大陆=四个模块，三颗功能星石=我的作品/成长足迹/天赋报告，星球上**已经有一只漂浮的「星球精灵」`star-spirit.svg`**。
- 结论：**桌宠向导方案完全可行，且与主题天然契合**——它就是这颗星球上原本就在的小精灵，不用新画角色、不用换世界观。

## 2. 方案命名：伯乐小星（桌宠向导）

把原本只在背景漂浮的星球精灵，升级为**有台词、有记忆、能指路的贯穿角色**：

- **形象**：复用 `star-spirit.svg`，新增 idle 动画（眨眼、轻微浮动、偶尔"思考"pose）。
- **位置**：首页为完整形态（星球旁悬浮 + 对话气泡）；进入模块后为**缩小 docked 形态**（角落小图标，点开才说话），保证引导连续但不挡操作。
- **性格设定**：温柔、好奇、爱鼓励孩子、永远只推一件事、从不直接给答案，而是用提问/邀请让孩子自己想。

## 3. 三层架构

```
┌─────────────────────────────────────────────────────────┐
│ 表现层（前端桌宠）                                          │
│  首页: 完整精灵 + 对话气泡 + 指引箭头(指向推荐大陆)          │
│  模块内: docked 小精灵，聊完/做完才冒泡                      │
│  状态: 首登?/当前引导阶段/上次推荐                          │
└───────────────┬───────────────────────────┬──────────────┘
                │ 取台词+下一步              │ 上报事件
                ▼                            ▼
┌──────────────────────┐      ┌──────────────────────────────┐
│ 智能体层 guide-agent   │      │ 状态层（既有）                 │
│ POST /api/guide        │      │ evidence_events（六维证据）     │
│  · 首登问候（确定性脚本）│      │ accounts / sessions（首登判定） │
│  · 聊后衔接（LLM 生成） │      │ chat.topic / child_words        │
│  · topic→模块 映射规则   │      │ interest_tags（待补，便宜）     │
│  · 兴趣激发引擎（无触发主动激发）│      │ 钩子库（信号→模块软桥接）      │
│  · 儿童安全护栏 + 兜底    │      │ getTalentEligibility（维度缺口）│
└──────────────────────┘      └──────────────────────────────┘
```

- **表现层**：纯前端组件，气泡打字机效果；首登阶段与引导阶段存 `localStorage`。
- **智能体层**：`guide-agent`，请求体带「孩子上下文」（年龄、最近话题、已完成模块、维度缺口），返回「台词 + 建议去的模块 + 理由 + 语气」。
- **状态层**：全部复用既有——不新建大表，只给 evidence 加一个 `interest_tags` 字段（便宜，来自上一版方案）。

## 4. 两个核心流程（你的原话场景）

### 场景 A · 初次登陆
1. 孩子进入「探索星球」首页，小星从星球后飘出，wave 动画 + 气泡：
   > "你好呀，我是伯乐小星 ⭐ 这颗星球上藏着你的超能力。我们先去聊聊你最喜欢做的事吧？"
2. 首页**高亮/脉冲**「聊天观察」大陆，气泡带按钮「去聊天 →」。
3. 点击 → `location.href = /chat.html?from=guide&onboard=1`，并在 `localStorage` 写 `guide.onboarded = true`、记录 `guide.lastGreeting = 'chat'`。

### 场景 B · 聊完之后
1. 孩子在聊天页点「返回星球」（我们已做的 `leaveChat` 会先 `finalizeConversation` 上报）。
2. 回首页后，表现层检测到"刚聊完"标记，向 `guide-agent` 请求衔接台词，传入：
   - `topic = 消防员`、`long_turn_count ≥ 2`（已判 strong/语言）、`child_words` 截片。
3. 小星气泡：
   > "你刚才说想当消防员，好酷！要不要去「职业模拟器」当一天消防员，看看都需要哪些本领？"
   - 同时理由字段：`because: "你刚才聊到了消防员"`。
4. 首页高亮「职业模拟器」大陆；跳转带种子 `?role=消防员`，职业模块内**该角色卡片高亮**（即上一版"模块间传种子"）。
5. 孩子玩职业 → 完成时 emit 带 `interest_tags:["消防/救护"]` + `completed` → 小星下次可说"你当消防员时很会照顾别人，这叫人际智能哦"。

> 这就是你说的"聊到消防员→推荐职业模拟器"的完整闭环，数据链路今天就已经具备 80%，只差 guide-agent 把它接起来。

### 场景 C · 聊完之后，但没聊到职业/故事（主动激发兴趣）
1. 孩子聊的是"我家的猫好可爱" → `finalizeConversation` 上报 `topic=宠物`、`child_words` 截片。
2. 回首页，guide-agent 发现 `topic` **未命中**职业/故事硬映射，进入**兴趣激发引擎**（§11）。
3. 引擎抽轻信号"喜欢小动物/动物" → 软桥接到「深海」→ 生成好奇心话术：
   > "你家的猫好可爱！你知道吗，海底还住着比恐龙还老的生物，会发光哦——要不要跟我潜下去看一眼？"
4. 首页高亮「深海」大陆；跳转带种子 `?hook=发光生物`，深海首屏弹出对应的"发光小鱼"引导卡。
5. 孩子玩深海 → emit `interest_tags:["海洋生物"]` → 下次小星可延续："你上次潜海看到的发光鱼，后来去哪了还记得吗？"

> 关键：**哪怕整轮对话零职业/零故事内容，向导也不会断片**——它靠"轻信号"而非"命中关键词"来桥接模块。

## 5. 智能体接口设计（guide-agent）

**端点**：`POST /api/guide`（可放在 `platform-core` 或独立 `modules/guide-agent`，建议独立便于扩展）

**请求体**
```json
{
  "child_name": "小朋友",
  "stage": "onboard" | "post_chat" | "post_module" | "return_home",
  "context": {
    "recent_topic": "消防员",
    "child_words": "我长大想开消防车去救人",
    "completed_modules": ["chat"],
    "dimension_gaps": ["spatial"],
    "last_module": "chat"
  }
}
```

**响应体**
```json
{
  "line": "你刚才说想当消防员，好酷！去职业模拟器试试当一天消防员？",
  "recommend_module": "career",
  "reason": "你刚才聊到了消防员",
  "tone": "encourage",
  "action_hint": "highlight_career"
}
```

**System Prompt 要点（儿童安全护栏）**
- 角色：伯乐小星，星球上的引导精灵，温柔好奇，永远鼓励。
- 长度：每句 ≤ 40 字；一次只说一件事、只推一个模块。
- 禁止：不输出外链、不暴露孩子真实姓名/学校、不替孩子下结论、不比较排名。
- 必须：推荐要带"因为……"的理由，理由只能来自传入的 `context`（不允许编造未发生的事件）。
- 输出：严格 JSON（`response_format: json_object`），与 `report-agent` 一致。

**兜底（关键，保证离线可用）**
- 若 `GUIDE_LLM_*` 未配置或超时 → 走规则生成器：
  - `topic` 命中映射表 `消防员→career`、`海洋/鱼→deep_sea`、`故事/公主→story` … 否则按 `dimension_gaps` 推一个最缺的维度对应模块。
  - 台词用模板拼装，保证"无 LLM 也能跑通首登→聊后衔接"的最小闭环。

## 7. 落地切片（建议顺序）

**MVP（零 LLM 依赖，今天就能验证 UX）**
1. 前端：首页加精灵 + 气泡 + 首登脚本台词 + 指向聊天大陆的脉冲箭头 + `localStorage` 引导阶段。
2. 前端：聊天 `finalizeConversation` 写 `localStorage.guide.justChatted = {topic, words}`（聊天模块已改好，加一行即可）。
3. 前端：回首页读该标记 → 按 `topic→模块` 规则映射表弹"去职业模拟器"气泡 + 高亮。
4. 效果：首登引导 + 聊后衔接闭环跑通，无需任何后端改动。

**V2（接智能体）**
5. 新增 `guide-agent`：确定性首登问候 + LLM 聊后衔接 + 规则兜底。
6. 模块内 docked 小精灵，做完/聊完才冒泡。
7. `interest_tags` 写入 evidence，支撑更细的兴趣→模块推荐。

**V3（闭环增强）**
8. 家长端：魔法书"成长故事线"里展示小星的引导轨迹（孩子被什么吸引了、串起了哪条路）。
9. 多轮引导记忆：小星记得"你上次说想当消防员，后来去试了吗？"

## 8. 风险与护栏

- **儿童安全**：LLM 输出长度/语气/禁外链/禁 PII 全部在 system prompt + 后置过滤双保险；规则兜底不参与任何外部模型。
- **隐私**：传给 LLM 的只有 `topic` + 截断 `child_words`，**绝不传完整对话 transcript**；走既有 `REPORT_LLM_*` 同源端点。
- **延迟**：LLM 调用异步，气泡先显示"打字中…"占位；首登问候用确定性脚本（免等待）。
- **推荐疲劳**：一次只推 1 条、带理由、可关闭（气泡右上角 × ），关闭后本次会话不再推。
- **不污染评估**：引导推荐是**独立层**，绝不改写 `strong/reference` 维度判定（沿用上版硬约束）。

## 9. 与其它串联方案的关系

桌宠向导是「叙事主线」，可叠加两条轻量方案形成合力：
- **兴趣星座（视觉层）**：在星球表面用细光带把"相关大陆"连起来（聊到消防→职业大陆亮起连线），纯装饰、零 LLM。
- **任务链（结构层）**：策划好的连续冒险（如"海洋学家之路"：深海→聊天→故事→职业），由小星分发给勋章。

推荐打法：**以桌宠向导为主 spine，兴趣星座做视觉呼应，任务链做深度玩法**——三者都挂在同一颗星球上，孩子感受不到"四个 App"，只觉得"我的星球在陪我探索"。

## 11. 无触发时的主动兴趣激发（兴趣激发引擎）

**问题**：孩子聊的是"猫 / 好吃的 / 怕黑 / 好无聊"，根本没碰职业或故事——向导还能引导吗？**能。** 关键在于把"话题→模块"的硬映射，升级成"**轻信号→好奇心缺口→任意模块**"的软桥接。这样向导才像"真的在听孩子说话"，而不是个关键词机器人。

### 11.1 机制四步
1. **轻信号提取**：LLM 从 `child_words` 抽 1–3 个"兴趣/情绪信号"（实体、情绪、能量值），不要求命中职业/故事。
2. **信号→模块软桥接**：用钩子库把任意信号映射到"最近模块"（见 11.2），允许跨域转接。
3. **好奇心缺口话术**：生成"不说教、留悬念"的邀请句（"你知道吗…要不要看一眼？"），而非"你应该去玩 X"。
4. **轮转 + 冷却**：优先推没体验过的模块，避免重复轰炸（见 11.3）。

### 11.2 各模块钩子库（示例，按兴趣信号桥接）
| 孩子聊到 | 接入模块 | 示例话术（好奇心缺口） |
|---|---|---|
| 猫/狗/动物 | 深海 | "海底住着比恐龙还老的生物，还会发光哦，想不想潜下去看一眼？" |
| 画画/涂色/手工 | 故事 | "星球上有本魔法书，能把你画的东西变成真的冒险，要不要试试？" |
| 星星/宇宙/火箭 | 星球探索 | "这颗星球旁边还有三颗你没去过的，要不要飞过去探险？" |
| 好吃的/食物 | 故事 | "听说故事大陆有座美食星球，云都是棉花糖做的，想去尝尝吗？" |
| 好无聊/没劲 | 任务链 | "那我们去点亮一颗还没亮的好奇星石吧！我藏了个小任务，敢不敢接？" |
| 怕黑/怕水（情绪） | 深海（温柔版） | "怕黑很正常～不过海底有自己带小灯笼的小鱼，一点都不黑，想认识它吗？" |
| 跑/跳/运动 | 职业 | "你跑得真快！星球上有个跑道世界，能当一天运动探险家，想挑战吗？" |

> 钩子库是**可运营的配置**（JSON），策划/家长可随时增删，不写代码。

### 11.3 轮转与冷却规则
- 优先级：**未体验模块** > 体验过但维度缺口大 > 已体验且无缺口。
- 同一模块冷却：3 次会话内 / 24h 内不重复主推。
- 首登后第一次"无触发"：优先推「故事」或「深海」（视觉强、最易被任意话题钩到，且最容易留下"哇"的瞬间）。

### 11.4 规则兜底（无 LLM 时也能激发）
按 `completed_modules` 求补集 → 取优先级最高未体验模块 → 从钩子库随机抽一句同模块话术。保证离线也能"主动推模块"，MVP 阶段即可跑通。

### 11.5 护栏（避免变成推销员）
- 一次只推 1 个，用"要不要"邀请而非"你应该"。
- 留好奇心缺口，**不剧透模块内容**（剧透就失去探索欲）。
- 尊重情绪：孩子累/低落时，只给"随时回来找我"的轻出口，不硬推。
- 气泡可关（右上角 ×），关闭后本次会话不再推。
- 激发层同样**不改写** `strong/reference` 维度判定（沿用 §8 硬约束）。
