# 四个模块的串联方案 · AI 伯乐探索星球

> 目标：把「四个互不相关的工具」变成「一个会记住孩子兴趣、互相推荐的探险世界」。
> 本文分两部分——**A. 创意愿景（不约束工程量）** 与 **B. 结合现状的落地路线**。

---

## 0. 问题诊断

四个模块（聊天观察 / 深海基地 / 故事共创 / 职业日常）目前是**四座孤岛**：

- 孩子侧：每个模块独立进入、独立玩、独立退出，**没有任何一个瞬间感觉到「它们是一家」**。
- 家长侧：后端把证据按六维聚合，但呈现出来只是「六根进度条」，看不到孩子完整的探索故事。
- 唯一连接点：后端的 `evidence_events` 表。这条连接在界面上**完全不可见**。

而我们已经采集到、却没人接住的信号：聊天模块 `finalizeConversation` 已经 emit 了 `topic`（话题）和 `child_words`（最长原话）；深海带 `title`、故事带 `child_words`、职业带 `completed_stages`。
**「孩子聊到消防员」这个信号，现在已经在采集了，只是从来没人拿去推荐下一个模块。**

---

## A. 创意愿景（不考虑工程量）

核心创意：**让「兴趣」成为在孩子身上流动的东西，而不是锁在后端的数据。**

### 概念名：探险航线 · 兴趣引力网（Constellation Routes）

孩子不是在做 4 个 App，而是在同一颗星球上走一条**连续的探险航线**。每到一个大陆，星球就「记住」他喜欢什么、擅长什么，并在下一站亮起一条通往相关大陆的路。

五个串联机制：

### 1. 伯乐向导（贯穿角色）—— 情感的胶水
一个 persistent 的向导角色，跟着孩子跨模块走，持有「你刚刚做了/说了什么」的短期记忆。
- 在聊天里聊到消防员 → 向导气泡：「你刚说想当消防员，要不要去职业模拟器当一天？」
- 不是弹窗广告，而是**有上下文、有温度的提醒**，出现频率低、每次只说一件。

### 2. 兴趣线索网（Interest Clue Network）—— 推荐的引擎
每个模块都向外发「兴趣信号」（topic / 角色 / 物种 / 关卡主题）。探索星球枢纽把这些信号织成**「推荐下一站」**，每条都带真实理由：
- 「你在聊天里展现了语言天赋 → 去故事共创写一段冒险」
- 「你在深海救了珊瑚 → 去职业模拟器当海洋生物学家」

### 3. 跨模块任务链（Quest Chains / 探险任务链）—— 设计的叙事
由策划预先编写的「多模块连续冒险」，有统一主题，完成整条链得专属勋章。
- 例：「海洋学家之路」= 深海(生态) → 聊天(讲述见闻) → 故事(写生物冒险) → 职业(当海洋生物学家)。
- 孩子感受到的是「一个完整故事」，不是四个按钮。

### 4. 故事接龙 / 上下文种子（Story Relay）—— 让作品延续
其它模块把「种子」喂给故事共创：
- 深海救下的生物 → 成为故事里的主角；
- 职业体验的角色 → 成为故事的场景；
- 聊天里的原话 → 变成故事的开头一句。
孩子会觉得「我之前玩的东西，在这里接着发生了」。

### 5. 双视角闭环（Two-way Loop）—— 孩子拉、家长推
- **孩子侧（兴趣拉动）**：基于「我喜欢什么」推荐下一步。
- **家长侧（洞察推动）**：魔法书新增「成长故事线」，把跨模块证据连成一句话故事 + 一个可执行建议——「这周小米在聊天展现语言天赋并聊到想当消防员，建议引导他体验职业模拟器的消防员角色，发展空间与逻辑智能」。

## B. 结合现状的落地路线

### 现状可复用资产

| 资产 | 现状 | 如何用 |
|---|---|---|
| 聊天 `topic` / `child_words` | 已在 finalize 时 emit | 直接作为兴趣信号源 |
| 深海 `raw_evidence.title` | 已有 | 作为「物种/主题」信号 |
| 故事 `child_words` | 已有 | 作为「叙事意图」信号 |
| 职业 `completed_stages` | 已有 | 作为「职业角色」信号 |
| 探索星球枢纽（PlanetHome/ThreeGlobe） | 已把模块做成星球表面 | 天然挂载「推荐下一站」与航线进度 |
| 六维聚合（getEvidence / getTalentEligibility） | 已读 evidence_events | 推荐引擎直接复用，不另起炉灶 |
| 我的作品 / 成长足迹 | 已跨模块聚合 | 任务链勋章、故事种子的天然落点 |

### 最小改动原则
- 推荐是**独立新增层**，绝不改动 `strong/reference` 维度判定逻辑（避免污染天赋判定）。
- 每次只给**一条**推荐，且必须带「为什么」。

### 分阶段路线

**P0 · 数据层（几乎零成本）**
- 证据 schema 增加可选字段 `interest_tags`（如 `["消防员","救援"]`）与 `thread_id`（属于哪条航线）。
- 聊天已具备 `topic`；补深海/故事/职业在 emit 时顺手填 `interest_tags`。

**P1 · 推荐引擎（新增 1 个轻量接口）**
- `GET /api/recommendation`：输入近期 evidence + 最新 topic，输出**一条**推荐。
- 两条规则：① 维度缺口——六维中哪维 `strong=0`，推荐能发展它的模块；② 话题匹配——`topic` 关键词匹配职业角色/模块主题。
- 纯规则即可起步，后续可换模型。

**P2 · 探索星球首页改版（枢纽生效）**
- 星球表面新增「推荐下一站」高亮路径 + 一句话理由。
- 新增「探险任务链」进度卡（已解锁/进行中/可领取勋章）。
- 伯乐向导气泡组件（低频次、可关）。

**P3 · 模块间上下文种子**
- 职业：接收 `?role=消防员` 高亮对应角色。
- 故事：接收 `?seed=` 把其它模块内容预填为开头/主角。
- 链接模式沿用已有的 `?from=ai-bole` 参数习惯。

**P4 · 家长魔法书「成长故事线」**
- 复用 report-agent 的聚合，把跨模块证据叙述成一段故事 + 建议。
- 这是把「六根进度条」升级成「一个成长故事」的关键一步。

### 最小可行切片（先做什么就能交付「消防员」例子）
`P0(聊天topic已具备)` + `P1 推荐接口` + `P2 首页推荐气泡` + `P3 职业接收 role 种子`。
这一刀下去，用户那个例子就跑通了：**聊到消防员 → 首页亮起职业模拟器 → 点进去消防员角色已高亮**。

## 风险与取舍

- **推荐疲劳**：一次只推 1 条、带理由、可忽略；宁少勿多。
- **维度纯净**：推荐层与六维判定解耦，不为了「串联」牺牲天赋评估严谨性。
- **家长可控**：推荐可整体关闭；职业匹配需注意儿童适宜性（白名单角色）。
- **隐私**：兴趣信号仅存于本地/账号内，不外流。
- **不过度设计**：任务链先做 1–2 条示范（海洋学家之路 / 星空诗人之路），验证手感再扩。

---

## 一句话总结

现在四个模块是「四座孤岛，只在后端共用一张六维表」；
目标是「一颗星球记得孩子的兴趣，主动把大陆连成航线——孩子被兴趣拉着走，家长看到一条完整的成长故事」。
最小改动即可先跑通「聊到消防员 → 推荐职业模拟器」这一条，再逐步铺开。
